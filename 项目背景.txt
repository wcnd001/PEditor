PEditor 项目背景（对应 PEditor v3.6）
====================================================

一、当前稳定基准
----------------

当前版本：PEditor v3.6。

当前代码以 PEditor v3.4 JS占位符与鼠标连击说明同步版为基准更新至 v3.6。v3.6 重点优化浏览器流程配置窗口：步骤修改自动保存、自动录制只显示结果、连接区与录制结果区左右可拖动、步骤编辑区与运行日志上下可拖动、定位值输入框支持长路径换行滚动；浏览器连接区标签和输入框采用行内紧凑布局。循环功能已重构为“循环开始/循环结束”循环块，可让多个连续浏览器步骤作为一组重复执行；循环块支持多个循环标记，例如 [[i]]、[[j]]，并允许输入/参数模板区域切换为多列表格，表格列名可作为循环标记或内容变量用于定位值、输入内容和 JavaScript 命令。本次补充优化还加入了复制步骤、全选操作、键盘按键点按/长按、跳转至步骤，并进一步优化浏览器连接区布局：标签按内容自适应，未超过连接区四分之一时完整显示、超过后自动换行；输入框紧贴标签并按当前行剩余宽度动态拉伸，右侧贴近连接区边界；调试端口和隐式等待位于同一行。主题设置继续扩展，新增表格标题行背景色和文字色配置，统一作用于数据库窗口、规则管理表格、浏览器循环内容表等表格控件，解决深色主题下标题行白底白字不可读的问题。

后续继续完善代码时，默认以该版本作为当前基准。教程和项目背景需要跟随代码同步更新，不再采用“稳定版再单独更新”的旧约定。

二、项目目标
------------

PEditor 是一个用于“工艺文本自动生成 + 字段内容快速复制 + 浏览器流程自动填报”的桌面工具。

核心流程为：

输入选项
    ↓
规则公式计算 / 数据库查询
    ↓
生成中间字段和最终字段
    ↓
工序模板中的 {占位符} 与 #公式# 替换
    ↓
生成完整工艺文本
    ↓
复制单个字段内容或导出到浏览器流程

当前版本已经实现浏览器自动化框架，不再只是预留接口。实际内网页面的具体按钮、输入框、弹窗和表格，需要在“浏览器配置”中按真实网页录制或手动填写定位值。

三、当前主要功能
----------------

1. 模板管理
- 新建模板、重命名模板、删除模板
- 导入模板、导出模板
- 每个模板保存自己的输入项、规则、复制按钮和浏览器流程配置

2. 输入选项
- 支持文本框、下拉菜单、可输入下拉菜单、复选框
- 支持固定选项、数据库选项和公式展开选项
- 输入区支持拖拽排序
- 模板选择固定在左侧输入区第一行，不参与输入值采集和排序

3. 工序模板
- 支持可用字段、已选字段和字段显示条件
- 支持模板预览
- 字段显示条件会影响主界面预览、复制按钮显示和浏览器字段池

4. 规则引擎
- 支持直接传递、数学公式、数据库查询
- 支持 {字段名} 占位符
- 支持 #表达式#、if(...)、and/or、and()/or()、int()、float()、round()、roundup()、abs()、isblank()、nl()
- 支持 dbjoin(...) 和 dbrows(...) 模板数据库函数

5. 数据库管理
- 管理 data.db 中的数据表
- 支持增删行、增删列、列移动、CSV 导入导出
- CSV 导入支持多种编码自动识别，建议优先使用 UTF-8

6. 复制按钮区
- 复制按钮列表保存在主模板 copy_buttons 中，与可用字段隔离
- 可从字段池新增复制按钮，删除后不会因字段仍存在而自动恢复
- 支持多选复制、批量删除、拖拽排序
- 横向滚动关闭，按钮按当前显示宽度自动换行
- 按钮文字不强制换行，按钮宽度按文字内容自适应
- 多行按钮独立排列，通过纵向滚动查看
- 选中和取消选中时都会复制对应字段内容
- 快速连续点击时不再频繁重排复制区

7. 浏览器自动化
- 通过 webcontrol.py 配置流程，通过 webengine.py 执行流程
- 支持启动受控 Chrome、读取窗口列表、切换目标窗口
- 支持自动录制页面元素，输出多种定位候选；v3.6 起自动录制只显示结果，不再自动填充或新建步骤
- 动作类型包括点击元素、输入文本、多选元素/多行选择、右键点击、全选操作、键盘按键、右键菜单项点击、下拉菜单两段式操作、等待元素、等待元素消失、等待新窗口、等待窗口关闭/回到主窗口、切换窗口、切换 iframe、拖拽元素、页面条件判断、跳转至步骤、添加表格、自动填单元格、执行JavaScript命令、鼠标连击等；其中点击元素、输入文本、执行JavaScript命令、鼠标连击支持 v3.6 循环配置，旧版“键盘组合键”仍兼容执行
- 点击动作已增强为多策略点击，适合处理部分弹窗确认按钮偶发点击失败的问题
- v3.3 调整为先执行普通点击，普通点击失败后再尝试 ExtJS fireHandler 兜底，避免 ExtJS 逻辑影响原本可正常点击的普通元素
- v3.3 补充新增“执行JavaScript命令”动作：填写定位值时，定位到的元素作为 JavaScript 的 arguments[0] 传入；未填写定位值时，直接在当前页面执行脚本
- v3.4 起，“执行JavaScript命令”改用 JS 专用字段占位符 [[字段名]]、[[__RESULT__]]，不再默认处理普通 {字段名} 和 #表达式#，避免破坏 JavaScript 对象字面量
- v3.4 新增“鼠标连击”动作，支持左键连击、右键连击和 1 到 20 次自定义连击次数；左键 2 次优先使用 Selenium 原生双击

8. 界面设置和主题
- 支持总字体缩放
- 支持选项区、工具栏、复制按钮区、预览框分别设置字号和紧凑程度
- 支持界面主题：浅色、深色、护眼、自定义
- 支持设置窗口背景、面板背景、文字、输入框、按钮、边框、选中颜色、拖动柄颜色、预览框背景、表格标题行背景和表格标题行文字等
- 界面设置窗口左右分割，左侧为字号设置，右侧为主题颜色设置
- 设置保存到 settings.json，旧设置缺少的新字段会自动使用默认值

9. 日志
- 通过 modify_log.txt 记录部分模板、数据库、浏览器流程等配置变化
- 可在程序内查看、刷新和清空日志

----------------

├── gui_helpers.py           # 通用 GUI 辅助函数，例如信号阻断和换行绘制标志
├── log.py                   # 修改日志写入和日志查看窗口
├── utils.py                 # 工具函数，主要处理 PyInstaller 打包后的资源路径
├── PEditor.spec             # PyInstaller 打包配置文件
├── settings.json            # 用户界面设置，运行时生成或更新
├── data.db                  # 主数据库文件，运行时使用
├── template.db              # 模板数据库文件，运行时使用
├── modify_log.txt           # 修改日志文件，运行时生成或更新
└── PEditor_教程.txt          # 使用教程，随代码版本同步更新

五、数据文件说明
----------------

1. data.db
- 保存用户业务数据表
- 主要供下拉菜单、规则数据库查询、dbjoin/dbrows 等功能使用

2. template.db
- 保存主模板、工序字段模板和浏览器流程配置
- 主模板主要保存输入项、规则、复制按钮等配置
- 工序模板主要保存 available_fields、available_field_names、selected_fields、field_conditions
- 浏览器流程主要保存当前模板对应的 browser_flows

3. settings.json
- 保存界面字号、紧凑程度、主题和颜色配置
- 不属于模板核心数据
- 删除后程序会使用默认界面设置重新生成

4. modify_log.txt
- 保存部分配置修改记录
- 不是程序运行必需文件

六、旧模板兼容说明
------------------

旧版本的 template.db 和 data.db 正常情况下可以继续在 v3.6 中使用。

注意事项：
- 使用新版程序前建议先备份旧 template.db 和 data.db
- 旧模板没有新增设置项时，程序会使用默认值补齐
- 复制按钮以主模板 copy_buttons 为准，不会因为可用字段存在而自动恢复已删除按钮
- settings.json 只是界面设置文件，旧版缺少主题颜色或表格标题行颜色字段不影响模板打开

七、浏览器自动化说明
--------------------

浏览器自动化依赖 Selenium 和 ChromeDriver。

v3.6 特别说明：
- 部分公司内网页面使用 ExtJS 框架，按钮真实点击逻辑可能不绑定在普通 DOM click 上，而在 ExtJS 组件 handler 中。
- v3.3 已将 ExtJS 点击调整为普通点击失败后的兜底，不再提前抢占普通点击。
- v3.3 补充新增自定义 JavaScript 步骤。Chrome 开发者工具中的 $0 不能直接写入程序步骤；如果控制台测试代码为 Ext.getCmp($0.id).fireHandler()，在程序中应改为 Ext.getCmp(arguments[0].id).fireHandler()，并填写该按钮的定位方式和定位值。
- v3.4 起，自定义 JavaScript 中如需插入字段值，请使用 [[字段名]] 或 [[__RESULT__]]。普通 {字段名} 和 #表达式# 在 JS 动作中不再替换。
- v3.6 起，点击元素、输入文本、执行JavaScript命令、鼠标连击支持循环设置，可使用 [[i]] 或 XPath 第一个纯数字下标批量定位。
- 需要网页原生双击时，优先使用“鼠标连击 -> 左键连击 -> 2 次”，不要用两个“点击元素”步骤代替。

常见配置：
- chromedriver.exe 路径
- chrome.exe 路径，可留空
- 启动 URL
- 调试端口，默认 9222
- 隐式等待时间

实际使用时，由于公司内网页面结构、弹窗、iframe、表格控件和前端组件不固定，浏览器流程需要在现场通过“自动录制”和手动调整定位值来完成。

建议：
- 能用稳定 name、placeholder、文本 XPath 时，不优先使用动态 id
- 慢页面优先使用等待元素或等待元素消失
- 弹窗和可选流程优先使用页面条件判断
- iframe 内元素必须先切换 iframe
- 每新增少量步骤就测试一次，不建议一次写完全部流程再测试

------------------

编写机器：
- Windows 10
- Python 3.8.10

目标运行机器：
- Windows 7
- Python 3.8 系列环境或 PyInstaller 打包后的 exe

主要依赖：
- PyQt5 5.15.9
- PyQt5-Qt5 5.15.2
- PyQt5_sip 12.15.0
- selenium 4.1.0
- pyinstaller 6.19.0
- pyinstaller-hooks-contrib 2026.4

数据和工具相关：
- sqlite3 为 Python 标准库
- csv、json、re、os、sys、time 等为 Python 标准库

九、打包说明
------------

当前项目使用 PyInstaller 打包。

示例命令：

pyinstaller --clean PEditor.spec --distpath "D:\Microsoft Visual Studio\code"

注意：
- 打包后 data.db、template.db、settings.json、modify_log.txt 等可写文件应放在 exe 同级目录
- chromedriver.exe 建议放在固定路径或 exe 同级目录，并在浏览器参数中填写
- 不要把旧数据库直接覆盖前的原始文件删除，升级前先备份

- 不动与功能改动无关的代码
- 用最少代码实现目标功能
- 不擅自添加用户未要求的附加功能
- 更新代码前应参考变量函数关系流程图.md

2. 文档更新原则
- 教程和项目背景跟随代码版本同步更新
- 新增、删除或调整功能时，应同步检查 PEditor_教程.txt 和 项目背景.txt 是否需要修改
- 当前两个说明文件对应 PEditor v3.6


十二、v3.6 循环与浏览器配置界面优化
----------------------------------

1. 浏览器步骤自动保存
- 删除“应用当前步骤修改”按钮。
- 步骤名称、动作、定位值、输入模板、循环参数等发生变化后会自动保存到当前模板流程。
- 保留“手动保存流程”按钮作为主动保存入口。

2. 自动录制简化
- 自动录制区只显示定位候选、XPath、CSS、iframe 链等结果。
- 删除“将录制结果填入当前步骤”“用录制结果新增步骤”等按钮，避免录制结果误改当前流程。

3. 循环能力
- 点击元素、输入文本、执行JavaScript命令、鼠标连击支持启用循环。
- 定位值可写 [[i]]，例如 //a[[i]]。
- 若定位值写成 //a[1]，程序也会在循环时自动替换第一个纯数字下标。
- 循环内容表可为每个序号配置不同文本或 JS 内容；留空则使用统一输入模板。

4. 界面调整
- 浏览器连接区更紧凑，输入框靠近左侧标签并按当前行剩余宽度动态拉伸，右侧贴近连接区边界；调试端口和隐式等待在同一行显示。
- 自动录制结果区放到连接区右侧并可拖动分割宽度。
- 步骤编辑区和运行日志之间改为上下可拖动分割。
- 定位值输入框支持自动换行、滚动浏览和高度限制，便于查看长 XPath。

5. 步骤操作与键盘动作补充
- 流程步骤列表新增“复制步骤”，复制当前步骤并插入到其后方，便于建立相似动作。
- 新增“全选操作”，专门执行 CTRL+A，避免旧键盘组合键在部分页面中触发不稳定。
- 原“键盘组合键”在新建步骤中调整为“键盘按键”，支持点按和长按常见按键；旧流程中的“键盘组合键”仍可兼容运行。
- 新增“跳转至步骤”，可无条件跳转到指定步骤，用于重复执行或流程分支。


七、模板转换工具说明
--------------------

本次循环重构不再保留旧版单步骤循环执行逻辑。随程序包额外提供模板转换工具，用于读取旧版 template.db，清理浏览器流程中的旧单步骤循环字段和新模板不再使用的冗余字段，并生成转换后的 template_converted.db。转换工具只处理模板数据库，不修改原始数据库，使用前仍建议备份 template.db。
