PEditor 项目背景（对应 PEditor v3.2）
====================================================

一、当前稳定基准
----------------

当前版本：PEditor v3.2。

v3.2 以 PEditor v3.1 九次修改版为基准，主要增加 ExtJS 内网页面按钮点击兼容处理。

后续继续完善代码时，默认以该版本作为稳定基准。除非特别要求，代码文件修改时不需要同时更新本文件和 PEditor_教程.txt；这两个说明文件在确认稳定版后再单独更新。

二、项目目标
------------

PEditor 是一个用于“工艺文本自动生成 + 字段内容快速复制 + 浏览器流程自动填报”的桌面工具。

核心流程为：

输入选项
    ↓
规则公式计算 / 数据库查询
    ↓
生成中间字段和最终字段
    ↓
工序模板中的 {占位符} 与 #公式# 替换
    ↓
生成完整工艺文本
    ↓
复制单个字段内容或导出到浏览器流程

当前版本已经实现浏览器自动化框架，不再只是预留接口。实际内网页面的具体按钮、输入框、弹窗和表格，需要在“浏览器配置”中按真实网页录制或手动填写定位值。

三、当前主要功能
----------------

1. 模板管理
- 新建模板、重命名模板、删除模板
- 导入模板、导出模板
- 每个模板保存自己的输入项、规则、复制按钮和浏览器流程配置

2. 输入选项
- 支持文本框、下拉菜单、可输入下拉菜单、复选框
- 支持固定选项、数据库选项和公式展开选项
- 输入区支持拖拽排序
- 模板选择固定在左侧输入区第一行，不参与输入值采集和排序

3. 工序模板
- 支持可用字段、已选字段和字段显示条件
- 支持模板预览
- 字段显示条件会影响主界面预览、复制按钮显示和浏览器字段池

4. 规则引擎
- 支持直接传递、数学公式、数据库查询
- 支持 {字段名} 占位符
- 支持 #表达式#、if(...)、and/or、and()/or()、int()、float()、round()、roundup()、abs()、isblank()、nl()
- 支持 dbjoin(...) 和 dbrows(...) 模板数据库函数

5. 数据库管理
- 管理 data.db 中的数据表
- 支持增删行、增删列、列移动、CSV 导入导出
- CSV 导入支持多种编码自动识别，建议优先使用 UTF-8

6. 复制按钮区
- 复制按钮列表保存在主模板 copy_buttons 中，与可用字段隔离
- 可从字段池新增复制按钮，删除后不会因字段仍存在而自动恢复
- 支持多选复制、批量删除、拖拽排序
- 横向滚动关闭，按钮按当前显示宽度自动换行
- 按钮文字不强制换行，按钮宽度按文字内容自适应
- 多行按钮独立排列，通过纵向滚动查看
- 选中和取消选中时都会复制对应字段内容
- 快速连续点击时不再频繁重排复制区

7. 浏览器自动化
- 通过 webcontrol.py 配置流程，通过 webengine.py 执行流程
- 支持启动受控 Chrome、读取窗口列表、切换目标窗口
- 支持自动录制页面元素，输出多种定位候选
- 动作类型包括点击元素、输入文本、多选元素/多行选择、右键点击、键盘组合键、右键菜单项点击、下拉菜单两段式操作、等待元素、等待元素消失、等待新窗口、等待窗口关闭/回到主窗口、切换窗口、切换 iframe、拖拽元素、页面条件判断、添加表格、自动填单元格等
- 点击动作已增强为多策略点击，适合处理部分弹窗确认按钮偶发点击失败的问题
- v3.2 新增 ExtJS 组件按钮点击兜底：部分内网页面的“确定/保存”按钮虽然表现为 <a> 或 <div>，但真实逻辑在 ExtJS 组件 handler 中；程序会尝试通过 componentid/id 获取 Ext.getCmp(...) 组件并执行 fireHandler()

8. 界面设置和主题
- 支持总字体缩放
- 支持选项区、工具栏、复制按钮区、预览框分别设置字号和紧凑程度
- 支持界面主题：浅色、深色、护眼、自定义
- 支持设置窗口背景、面板背景、文字、输入框、按钮、边框、选中颜色、拖动柄颜色、预览框背景等
- 界面设置窗口左右分割，左侧为字号设置，右侧为主题颜色设置
- 设置保存到 settings.json，旧设置缺少的新字段会自动使用默认值

9. 日志
- 通过 modify_log.txt 记录部分模板、数据库、浏览器流程等配置变化
- 可在程序内查看、刷新和清空日志

四、项目文件结构
----------------

PEditor/
├── PEditor.py               # 主程序入口，主界面、模板管理、动态表单、界面设置、复制按钮区
├── dbutils.py               # 主数据库 data.db 的底层 SQLite 操作封装
├── datamanager.py           # 数据库管理窗口，管理数据表、列、行、CSV 导入导出
├── template_db.py           # 模板数据库 template.db 操作，管理主模板、字段模板、浏览器流程
├── template_editor.py       # 工序字段模板编辑窗口，可用字段、已选字段、字段显示条件、模板预览
├── datamatch.py             # 规则引擎，规则管理、公式解析、占位符替换、数据库函数
├── webcontrol.py            # 浏览器流程配置窗口，步骤编辑、自动录制、流程保存
├── webengine.py             # Selenium 浏览器执行引擎，执行点击、输入、窗口、iframe、条件判断等动作
├── export.py                # 导出模块，连接主界面数据与浏览器执行引擎
├── gui_helpers.py           # 通用 GUI 辅助函数，例如信号阻断和换行绘制标志
├── log.py                   # 修改日志写入和日志查看窗口
├── utils.py                 # 工具函数，主要处理 PyInstaller 打包后的资源路径
├── PEditor.spec             # PyInstaller 打包配置文件
├── settings.json            # 用户界面设置，运行时生成或更新
├── data.db                  # 主数据库文件，运行时使用
├── template.db              # 模板数据库文件，运行时使用
├── modify_log.txt           # 修改日志文件，运行时生成或更新
└── PEditor_教程.txt          # 使用教程，稳定版确认后单独更新

五、数据文件说明
----------------

1. data.db
- 保存用户业务数据表
- 主要供下拉菜单、规则数据库查询、dbjoin/dbrows 等功能使用

2. template.db
- 保存主模板、工序字段模板和浏览器流程配置
- 主模板主要保存输入项、规则、复制按钮等配置
- 工序模板主要保存 available_fields、available_field_names、selected_fields、field_conditions
- 浏览器流程主要保存当前模板对应的 browser_flows

3. settings.json
- 保存界面字号、紧凑程度、主题和颜色配置
- 不属于模板核心数据
- 删除后程序会使用默认界面设置重新生成

4. modify_log.txt
- 保存部分配置修改记录
- 不是程序运行必需文件

六、旧模板兼容说明
------------------

旧版本的 template.db 和 data.db 正常情况下可以继续在 v3.2 中使用。

注意事项：
- 使用新版程序前建议先备份旧 template.db 和 data.db
- 旧模板没有新增设置项时，程序会使用默认值补齐
- 复制按钮以主模板 copy_buttons 为准，不会因为可用字段存在而自动恢复已删除按钮
- settings.json 只是界面设置文件，旧版缺少主题颜色字段不影响模板打开

七、浏览器自动化说明
--------------------

浏览器自动化依赖 Selenium 和 ChromeDriver。

v3.2 特别说明：
- 部分公司内网页面使用 ExtJS 框架，按钮真实点击逻辑可能不绑定在普通 DOM click 上，而在 ExtJS 组件 handler 中。
- 这类按钮常见特征包括 class 含 x-btn、属性含 componentid、id 类似 button-1291。
- v3.2 已在 webengine.py 中加入 ExtJS fireHandler() 点击兜底，用于提高“确定”“保存”等按钮自动点击成功率。

常见配置：
- chromedriver.exe 路径
- chrome.exe 路径，可留空
- 启动 URL
- 调试端口，默认 9222
- 隐式等待时间

实际使用时，由于公司内网页面结构、弹窗、iframe、表格控件和前端组件不固定，浏览器流程需要在现场通过“自动录制”和手动调整定位值来完成。

建议：
- 能用稳定 name、placeholder、文本 XPath 时，不优先使用动态 id
- 慢页面优先使用等待元素或等待元素消失
- 弹窗和可选流程优先使用页面条件判断
- iframe 内元素必须先切换 iframe
- 每新增少量步骤就测试一次，不建议一次写完全部流程再测试

八、开发与运行环境
------------------

编写机器：
- Windows 10
- Python 3.8.10

目标运行机器：
- Windows 7
- Python 3.8 系列环境或 PyInstaller 打包后的 exe

主要依赖：
- PyQt5 5.15.9
- PyQt5-Qt5 5.15.2
- PyQt5_sip 12.15.0
- selenium 4.1.0
- pyinstaller 6.19.0
- pyinstaller-hooks-contrib 2026.4

数据和工具相关：
- sqlite3 为 Python 标准库
- csv、json、re、os、sys、time 等为 Python 标准库
- charset_normalizer、chardet 在数据库 CSV 导入中作为可选编码识别增强，缺失时程序会回退到内置编码尝试列表

九、打包说明
------------

当前项目使用 PyInstaller 打包。

示例命令：

pyinstaller --clean PEditor.spec --distpath "D:\Microsoft Visual Studio\code"

注意：
- 打包后 data.db、template.db、settings.json、modify_log.txt 等可写文件应放在 exe 同级目录
- chromedriver.exe 建议放在固定路径或 exe 同级目录，并在浏览器参数中填写
- 不要把旧数据库直接覆盖前的原始文件删除，升级前先备份

十、后续维护约定
----------------

1. 代码修改原则
- 不动与功能改动无关的代码
- 用最少代码实现目标功能
- 不擅自添加用户未要求的附加功能
- 更新代码前应参考变量函数关系流程图.md

2. 文档更新原则
- 平时完善代码时，不需要一同给出 PEditor_教程.txt 和 项目背景.txt
- 当某一版确认稳定后，再单独要求更新这两个文件
- 当前两个说明文件对应 PEditor v3.2
